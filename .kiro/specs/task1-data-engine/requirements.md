> Kiro 規格驅動開發：需求層定義「要滿足什麼」，不描述「怎麼做」。
> 設計見 [design.md](./design.md)，任務拆解見 [tasks.md](./tasks.md)，
> 實作過程中被實測推翻的假設記錄於 [development-log.md](./development-log.md)。

## R0. 背景與範圍變更

命題文件原以金管會信用卡統計為示範資料。主辦方後續說明**決賽現場提供 11 份
旅遊業務 Excel，欄位結構與業務指標事先未知**，並要求系統能吃通用 Prompt
一步到位生成簡報。

因此本模組的需求從「信用卡指標函式庫」改為**領域無關**：資料目錄 +
白名單運算積木 + LLM Function Calling。開發期以旅遊資料為主要測試集，
信用卡資料保留作為「多工作表、期間為欄」的第二種版面驗證。

## R1. 資料正確性（最高優先）

| 編號 | 需求 | 驗證方式 |
|---|---|---|
| R1.1 | 所有數值由程式從原始 Excel 計算，LLM 不參與任何算術 | 積木為純函式；LLM 輸出只含積木名與欄位名，不含數值 |
| R1.2 | 抽查數值與原始 Excel 逐格一致 | 隨機抽樣回原檔核對儲存格 |
| R1.3 | 自行加總的結果須與報表既有的總計欄相符 | 明細加總 vs 官方總計欄，容忍 0.5% |
| R1.4 | 同一 Prompt 重跑結果一致 | 積木純函式、不修改輸入；LLM temperature = 0 |

## R2. 可追溯性

每個輸出的數值都必須能回答「這個數字從哪來、怎麼算的」：

- **來源座標**：檔案、工作表、A1 儲存格範圍。**必須是真實 A1 表示法**，
  不接受「日本@2024」這類偽座標——偽座標無法讓人打開 Excel 逐格核對。
- **積木調用鏈**（`block_chain`）：依序記錄呼叫了哪些積木與參數。
- **計算假設聲明**（`assumption_statement`）：對業務定義的理解，
  例如分母如何界定、期間如何取。
- **校驗狀態**（`validation_status`）：`passed` / `na` / `failed` /
  `needs_manual_review`。

## R3. 通用運算積木

10 個領域無關的統計原語，任何業務指標皆為其組合結果，換領域不新增函式。

### 積木清單與邊界條件

| 積木 | 邊界條件 |
|---|---|
| `filter(column, operator, value)` | 運算子走白名單；不支援任意運算式字串 |
| `filter_by_period(start, end)` | 含頭含尾；期間為空的列一律排除 |
| `group_sum(group_col, value_col, detail_only)` | 預設排除小計與總計欄，保留殘差欄 |
| `group_mean(...)` | NaN 不計入分母，不補 0 |
| `rank_top_n(value_col, n, ascending)` | 並列名次採 `method='min'`；n 須為正整數 |
| `pivot(index, columns, values)` | 重複組合以加總合併，行為明確不採 pandas 預設 |
| `join(a, b, on, how)` | 僅開放 inner／left／outer，禁止 cross |
| `cumulative_sum(value_col, order_by)` | 先排序再累計 |
| `ratio(numerator, denominator, as_percent)` | **分母為 0 → N/A 附原因**，不回傳 0 或無限大 |
| `growth_rate(current, previous)` | **缺基期／基期為 0／基期為負 → N/A 各附原因** |

### N/A 規則（R3.1）

缺少資料時**必須輸出 N/A 並附原因，絕不估算**。0 與 N/A 語意完全不同：
「日本旅客占比 0%」會被寫進簡報當結論，「當年無資料所以占比無意義」才是事實。

## R4. 資料目錄（Data Catalog）

### R4.1 內容範圍
**一欄一張卡，不是一格一張卡**：只記錄欄位的「地址與意思」（欄名、單位、
儲存格範圍、少量樣本值、信心分數），不含任何列的實際數值。

### R4.2 欄位語意比對信心門檻

| 區間 | 處置 |
|---|---|
| ≥ 0.85 | 自動採用 |
| 0.6 ～ 0.85 | 採用但標記，供人事後抽查 |
| < 0.6 | 不採用，列入 `needs_manual_review` |

### R4.3 比對方法
比對「數值的結構特徵」而非欄名字串：值域、量級、整數性、單調性，
加上單位關鍵字與中英雙語表頭模式。**即使欄名亂寫、順序打亂、中英夾雜，
只要數值統計特徵不變，信心分數就穩定**——這是換領域也能用的關鍵。

## R5. 結構解析

須正確處理以下真實情境（皆為實測遭遇，非假想）：

- 多層合併表頭（最多 3 層），且**表頭層數不可從合併儲存格數量推斷**
- 資料起始列不固定（實測分佈第 3～5 列）
- 寬表轉長表，且 melt 後仍保留 A1 座標
- 民國與西元年並存字串：`53年1964`、`66 年 1977`、`民國106年`
- 期間代碼作為欄名：`11401`（民國年月）、`202401`（西元年月）
- **兩種版面方向**：年度為列（旅遊報表）與期間為欄（財報）
- 異常負數佔位值：須區分「比率欄負成長」（正常）與「量值欄負數」（異常）
- 各檔起始年份不一
- 輸入格式：`.xlsx` / `.xlsm` / `.xls` / `.csv`；
  **不支援的格式必須明確報出，不得靜默略過**

## R6. LLM 約束

| 編號 | 需求 |
|---|---|
| R6.1 | LLM 只讀 Data Catalog，不讀原始 Excel |
| R6.2 | LLM 只能呼叫白名單積木，以 structured output 的 enum 強制約束 |
| R6.3 | 欄位參數只能取自 Catalog 的 canonical 名稱，禁止自由輸入字串 |
| R6.4 | `value` / `source` / `validation_status` 一律由程式填入 |
| R6.5 | 模糊語意輸出非阻斷式假設聲明並繼續，不中斷詢問使用者 |
| R6.6 | LLM 不可用時（憑證失效、逾時、額度用盡）須有規則式後備 |

## R7. Sanity Check 與重試

- 檢查項目：比率範圍、分母非 0、非 NaN／Inf、明細加總與官方總計對帳、
  同一欄位跨檔案重複計算
- 失敗處置：回饋 LLM 重組積木，**最多重試 2 次**，仍失敗標記
  `needs_manual_review`
- **N/A 不算失敗**：系統誠實回報「算不出來」正是要的行為；
  當成錯誤會逼下游用 0 填補，反而製造假數字

## R8. 輸出

### R8.1 同源
`analysis_result.json`（metric + chart_data）、`analysis_result.xlsx`、
`data_lineage.json` **必須由同一份計算結果物件分別序列化**，
不可各算各的，也不可由 LLM 把 JSON 轉成 Excel。

### R8.2 三方一致
chart_data、`analysis_result.xlsx` 與 metric JSON 的數值須**逐格一致**，
以嚴格相等比對（非容差比對）。

### R8.3 識別碼唯一
`metric_id` 在單次輸出中必須唯一。同一概念在不同檔案有不同統計口徑時
（同一批對象的兩種量法），須產生不同的 metric_id。
